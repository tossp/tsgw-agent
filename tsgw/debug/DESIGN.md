# TSGW 任务大盘：信息覆盖、设计与验收

## 本轮授权与交付边界

用户将独立 `/debug` 定义为当前实例的任务大盘，而非上游 Debug 的简化版本；诊断是其中一层。上游已有的运行态诊断信息是覆盖基线，并提供任务家族及较完整的视觉设计。用户后续明确移除独立“任务全景”和历史目录展示，只保留运行态资源，并将系统观测移到最左。用户允许适量 SVG、素材与动效，参考 `login2`，不以工作区极简风格限制大盘。

首轮整改已按后续授权发布并部署；上一轮信息密度整改已另行获准提交并合入本地 fork 分支 `tsgw`。当前多会话资源及家族网格整改已完成独立工作树中的前端实现与验证，用户随后明确授权提交、合入 `tsgw` 并推送发布 npm `next`；本轮不包含服务器部署，不沿用旧轮次部署授权。**未经另行明确确认，禁止新增或调整后端接口、返回字段、参数和行为。** 模块外接入清单见 [模块规则](AGENTS.md)，不修改上游 `DebugPanel` 或聊天生命周期。

## 数据来源与语义

- `GET /api/agent/debug[?session=]`：每 2 秒检查轮询，最多一个 Debug 请求在途。首次读取全局摘要，随后在全部驻留 ID（含子代理）间公平轮换，各自缓存详情与服务端时钟。稳定 N 个会话时，每份详情约 2N 秒更新一次，慢请求或隐藏页会延长；全局摘要仍来自最近成功的 GET。取消选择和历史优先采样，仅自动轮转当前驻留会话，不激活会话。summary 覆盖 wrapper 与 agent stream 登记，不代表所有任务和历史执行轮次。
- `GET /api/sessions`：每 30 秒读取名称、项目、分支、普通／子代理／fork 关系与持久化子代理状态，仅作当前驻留会话的元数据；不展示完整目录或采样历史会话。保留元数据接收时间与不同采样周期，不能将两接口当作原子快照。
- `GET /api/agent/<id>?systemPrompt=0`：复用宿主状态接口读取 `state.model.{provider,id}` 与 `state.thinkingLevel`，不读取默认设置或历史来猜当前值。每次资源查询至多发起一个串行状态 GET；未驻留返回 `running=false`，不启动会话。宿主 `get_state` 不重置 idle 或最近命令；失败保留自己的旧采样并标注，未读到的字段显示未知。
- 本页真实观测：Debug／目录 GET 请求耗时、成功／失败计数、在途时间、协议和页面可见性；明确不代表另一个聊天页面。
- 运行态指服务器持有对应信息，不等同正在执行；`running=false`、无 wrapper、目录存在或消失都不证明任务成功。下一次 idle 检查不等同关闭时间，Stop 强制关闭单独标注。
- 服务端读取失败可能回退空值，接口没有每源错误标志。因此使用“快照已更新／过期”等措辞，而非宣称整个实例健康。

## 页面方案

1. 紧凑品牌栏：保留档案视觉、时钟、新鲜度、复制与返回入口，桌面高度不超过 80px，不用大面积装饰占首屏。
2. 单行六项概览：普通会话、子代理分别计数，显示各自执行数量，并保留执行总数、等待输入、运行态总数和 SSE。缺少快照时不显示运行态零值。
3. 左侧关注信号／轮询／服务器资源，右侧为运行态任务家族网格；独立任务全景整体移除。每个家族使用一个外框，主代理与子代理共处其内，子行缩进、不单独开列或套大卡片。项目只作家族头元数据，不把同项目所有主会话塞进一块。主名称只在家族头展示一次，子代理的名称／身份／profile 保留两行层次。按资源区实际宽度单／双／三列，末行利用余宽；主框架在 1366×768 和 1440×900 一屏可扫描，至少三个普通主会话资源同屏。更多记录在整个资源区滚动，没有每卡滚动条或内容折叠，手机纵向单列，不靠缩字号。
4. 仅当前运行态（执行、等待、空闲驻留、关闭中），不展示历史目录或提供搜索／筛选／选择切换。子代理使用自己的状态与检查时间；不驻留的家族根仅作父级关系标题，不铺旧资源、模型、采样等待或检查条，也不增加运行计数。多级子代理仍为根家族＋单层子行，直接父关系按 `relation` 明确显示；fork、侧聊分别独立成根并注明来源。沿用 v0.14.1 的 `dashboardRole()`，目录已确认的侧聊不能因 summary／wrapper 的通知抑制标志被误判为子代理；目录缺失的识别限制仍保留。
5. 资源区采用连续字段行：MCP 灯态与释放条、唯一回收检查倒计时及条、执行／等待标签、合并事件流、provider 与进程历史。不是靠新增折叠、隐藏字段或缩字号解决密度。主代理与子代理沿用相同行式结构，子代理归入家族缩进，不单独开列或做大胶囊；不重复铺主会话内的子代理卡片。资源头第二行放身份／状态／profile，后续行保留描述和真实父级；目录状态明确标明来源，不冒充实时执行状态。正常连接灯保持稳定，连接中虚线呼吸、错误实线、释放点线，状态不只依赖颜色。
6. 左侧两种真实 GET 轮询分别显示耗时、慢／在途／失败、计数和样本；下次轮询检查不等于保证请求发起（隐藏页暂停，在途不叠加）。未观测状态不标正常；观察页状态不冒充其他聊天页客户端遥测。
7. 所有驻留资源自动采样与展示，无需先选会话；退出后清缓存，旧全局回复不能把退出详情填回。未采样时展示该会话 summary 的真实回收检查条，详情采到后切换为该份详情的服务端时钟，不能重复或借用其他会话旧详情。不写 URL，不发送任务命令。
8. 移除“观测边界”整块开发说明，相关限制保留在本文及模块规则。页面只提示当前数据尚未采样、过期或读取失败，不把未知显示成正常。

视觉保留 `login2` 的品牌、双弧准星、编号与边角；按用户本轮追加意见改为现代深色控制台，而非暖白档案纸：石墨蓝背景、分层蓝灰面板、电青强调，紫色区分子代理，绿灯和橙红分别表达连接／等待／异常。大盘配色局限模块内部，不切换聊天工作区主题。渐变、细网格与光晕适度使用，文字对比和状态辨识优先。SVG 仅作装饰，不生成假指标；动效不阻挡阅读，不复制登录的开场等待或播报，减少动态效果时停止。需要保留键盘操作、可见焦点与手机无横向溢出。
