## 本轮采用

`ImDriver.setTyping` 为可选能力，Telegram 保持现有行为。微信在已接收入站、聊天队列开始时开启状态；等待共享会话、处理排队消息和发送最终回复期间维持，队列排空或停止后取消。

票据按本次忙碌周期获取，只留内存。续显与取消按序执行，旧状态取消结束后才开始新状态；停用驱动时取消待处理请求，并完成独立的状态取消请求。状态失败按 `typing` / `typing-stop` 阶段上报 CAT，不阻断任务和正文回复，不附带外部错误、凭据或聊天正文。

图片按原始字节传入现有 wrapper 的 images；文件落盘后在用户消息内写入精确本地链接，Web 沿用会话文件引用访问，不新增全局目录授权。下载通过入站准备回调放进聊天队列，可由 `/stop` 取消；正文/引用/附件形成同一次来源明确的 Pi 请求。微信最终附件只取该请求最终答复中的显式本地 Markdown 链接并依次发送；正文、附件上传和输入状态共用聊天生命周期。

## 后续建议与决定边界

1. 图片/文件双向、语音转写文本和 inline 引用文字已实现；下一步以手机实测确认图片可见、文件可打开、引用可理解和停止后无晚到附件。
2. 后续可评估视频、无转写语音、ID-only 引用和旧引用附件；工具进度先确认手机可见效果，再决定事件映射。
3. 新版 PIN/实名扫码按实际账号需要安排；主动投递先核验 token 条件。群聊、多人、原生语音出站、撤回编辑、按钮和同气泡流式，先取得明确官方依据或单独获准实测。

以上待选事项均与本轮图片/文件、转写、引用文字及输入状态分开决定。`context_token` 无固定窗口证据，不套用其他微信产品的 24/48 小时规则；官方暂停 1 小时、typing 配置缓存和引用缓存期限均不是消息有效期。媒体大小、时长、频率限制也不能从客户端限额外推。

当前客户端声明 `channel_version=2.4.6`。官方 main 的包版本不代表服务端最低版本；未核验兼容范围前不随调研盲改版本字符串。
