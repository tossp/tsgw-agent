# 微信接入

在「设置 → 即时通讯」填写机器人名称和项目绝对路径，点击「获取微信二维码」，在微信扫码并确认。机器人只接受扫码绑定主人的私聊。二维码由服务端本地生成。已有账号重新扫码会更新凭据并保留项目和会话关联。当前支持基础扫码流程，平台额外要求配对码时可能无法完成绑定。

微信驱动通过长轮询接收消息。收到一条普通消息后，IM 会查找已绑定的普通 Pi 会话。已有绑定时复用原会话，原会话正忙时由 Pi 排入后续队列。没有有效绑定时在项目里创建普通会话并保存关联。设置页可以手动指定同项目已有会话。

微信输入在 Web 中显示为 Pi 原生通知。模型处理后通过 `im_send` 回复，文字、图片和文件可组合或分次发送。也可在普通 Web 会话里明确指定当前项目的微信机器人名称或 ID，让模型主动发送。微信驱动会使用该机器人已建立的聊天上下文，尚无发送上下文时，需要先从微信向机器人发过消息。

## 消息与附件

- 入站支持文字、图片、文件、平台提供的语音转写和 inline 引用。收到视频或无转写语音时会给出提示。引用中的命令不作为控制命令执行。
- 出站支持文字、图片和文件。`im_send` 的 `items` 按顺序处理，工具按项返回结果。长文字自动分段。发送失败后，后续项交由模型根据实际结果处理。
- 客户端支持单张图片 10 MiB、单条入站最多 10 张图片、单文件 100 MiB。下载文件保存在 agent 目录下，供模型和历史通知按原路径查看。输入状态覆盖入站准备和通知提交，由微信驱动管理票据和续显。

| 命令 | 行为 |
| --- | --- |
| `/help`、`/start` | 显示用法 |
| `/status` | 查看项目和当前关联会话 |
| `/sessions` | 列出项目内可关联的普通会话 |
| `/bind 会话ID` | 关联已有普通会话 |
| `/new` | 解除绑定，下条消息创建新会话 |
| `/stop` | 取消准备中的输入并停止当前关联会话，包括其 Web 任务 |

## 保存与恢复

配置、凭据、绑定、游标及去重数据位于 Pi agent 目录下的 `integrations/im/state.json`，权限为 `0600`。服务重启时恢复启用的微信连接。历史 Telegram 配置保留，当前版本暂停 Telegram 接入。修改机器人项目时会清除旧关联，原 Pi 会话保留。已有会话文件沿用原始内容。

连接与发送错误分别显示。发送结果不明时驱动不会重试。附带句柄的通知依照 Pi 原生会话机制保存，可用于同一会话的后续回复。收件后遇停机的待处理通知和发送调用不会自动重放。

## 验证

```sh
node --experimental-strip-types --test tsgw/im/*.test.mjs
node_modules/.bin/tsc --noEmit --incremental false
npm run lint
IM_E2E_URL=http://127.0.0.1:30141 node tsgw/im/e2e.mjs
```

浏览器回归拦截 IM 管理请求，协议测试使用模拟 HTTP，宿主集成使用真实 Pi SDK 和模拟模型。真实微信扫码、发送及手机媒体显示需要单独实测。更多细节见 [接入契约](DESIGN.md)、[微信能力对照](WEIXIN_CAPABILITIES.md) 和 [第三方许可](THIRD_PARTY_NOTICES.md)。
