# 微信与 Telegram

在「设置 → 即时通讯」中添加机器人。每个机器人绑定一个现有项目目录，沿用该项目的 Pi 模型、工具和扩展配置；服务端使用长轮询，不需要公网回调地址。

## Telegram

1. 从 BotFather 获取机器人 Token。
2. 填写名称、项目绝对路径和允许使用的 Telegram **数字用户 ID**（不是 `@username`）。多个 ID 用逗号或换行分隔。
3. 需要限制到指定私聊或群聊时，填写允许的聊天 ID；群聊 ID 通常为负数。不填则允许上述用户在任意聊天中使用机器人。
4. 创建后，私聊直接发送文字；群聊中 @ 机器人、使用 `/command@机器人用户名`，或回复机器人的消息。

只有允许名单中的用户可触发任务或控制命令。群聊按聊天关联会话；Topic 再独立区分，不同群、Topic、私聊和机器人不会自动合并。群内其他成员仍可能看到机器人在群中发送的回复。

## 微信

填写名称和项目目录，点击「获取微信二维码」，用微信扫码并确认。仅扫码返回的主人账号可以发送任务；这不是企业微信接入，也不支持微信群。

收到任务后显示微信原生「正在输入」状态，每 5 秒续显，覆盖等待共享会话、消息排队、处理和最终回复发送。队列处理完、任务停止或机器人停用后取消；状态请求失败单独报遥测猫，不影响正常回复。输入票据只保存在内存。官方能力与本项目接入差异见 [微信能力对照](WEIXIN_CAPABILITIES.md)。

二维码在本机生成，Token 仅保存在服务端。取消扫码会终止待确认授权；授权已确认并开始保存时会提示等待绑定完成，此时不能再取消。已有账号重新扫码用于更新凭据，不清空原项目和会话关联。若平台要求额外配对码或返回已绑定重定向，界面会提示绑定失败；当前流程未提供配对码输入，不能保证这些账号可通过本入口重新绑定。

## 微信图片、文件与语音转写

微信可接收图片、文件及带平台转写文字的语音，一条消息里的图片和文件按原顺序处理。图片以原始字节随消息交给模型；文件保存在本机，模型通过消息中的附件链接读取，文档内容能否解析取决于项目已有工具。语音没有转写文字或收到视频时会明确提示改发文字、图片或文件。

入站引用的文字、语音转写和摘要与当前正文分开传给模型，引用里的 `/stop` 等不会作为控制命令执行。仅包含消息 ID 的引用会提示平台未提供原文；当前没有历史引用缓存，也不下载引用里的旧附件。

需要交付图片或文件时，助理在最终答复写出明确的本地 Markdown 图片/文件链接，系统将其上传为微信附件，依次回到本次原聊天。只处理最终答复的显式链接，同一文件只发一次；代码示例、工具结果、远端 URL 和裸路径不自动触发发送。Web 保留原答复，微信文本用附件名称替换路径；附件不可用时给出提示。Telegram 仍只收发文字。

客户端当前限制每张图片 10MiB、每条最多 10 张图片、单文件 100MiB，媒体传输时限 60 秒；这些是客户端限制，不是微信平台硬上限。附件位于 agent 目录的 `integrations/im/media/<机器人ID>/<随机目录>/`，保留用于模型处理与历史查看，不自动清理。附件下载在聊天队列内执行，不阻塞长轮询；`/stop` 可取消下载和上传。媒体请求及下载票据、AES 密钥沿用本模块的遥测隔离，失败只上报安全阶段。

## 项目和会话

- 收到消息时，先找这个对话已经关联的 Pi 会话。有则恢复；没有关联或原会话已删除，则在机器人绑定的项目中新建。
- 不自动选择项目中最近的一条会话。可以在机器人详情页选择项目内已有的普通会话，或通过 `/sessions` 和 `/bind` 手动关联。
- 原会话正在执行 Web 任务时，IM 等它结束后再提交。会话执行期间另有 Web 消息插入，无法确认本次答案归属时会提示到 Web 查看，避免把混合输出发给 IM。
- 修改机器人项目会清除旧项目的会话关联；原 Pi 会话不会删除。删除机器人也只删除 IM 配置与关联。
- `/stop` 会停止当前关联会话的任务（包括从 Web 发起的任务），并撤掉当前 IM 对话尚未提交的输入。停用机器人只停止连接和回复等待，不主动中止共享的 Pi 任务。

| 命令 | 行为 |
| --- | --- |
| `/help`、`/start` | 显示用法 |
| `/status` | 当前项目和关联会话 |
| `/sessions` | 列出项目内可关联的会话 |
| `/bind 会话ID` | 关联已有普通会话 |
| `/new` | 解除旧关联，下一条消息新建会话 |
| `/stop` | 请求停止关联会话，并撤掉本聊天尚未提交的输入 |

## 消息来源与回复

Web 显示共享会话里的完整往来。通过微信或 Telegram 发起的用户消息带对应来源角标，普通 Web 输入保持原样；角标在实时接收、刷新及历史翻页时一致。其他渠道可以手动关联同一个普通会话，各自发起的任务仍只回到原聊天或 Topic，Web 输入与回复不会自动广播给 IM。

每次 IM 输入的来源和回复地址保存在该 Pi 会话 `.jsonl` 的 `pi-web:im-source` custom entry，通过 `messageEntryId` 关联具体用户消息，包含渠道、机器人、聊天/Topic、发送者、平台消息 ID 和请求 ID。Meta 不含平台凭据，也不进入模型上下文；Web 的正文投影隐藏内部请求标记。历史上只有正文来源说明、没有 Meta 的旧消息不会自动补角标。

## 保存与限制

数据位于 Pi agent 目录下的 `integrations/im/state.json`（默认 `~/.pi/agent/integrations/im/state.json`），文件权限为 `0600`。其中含机器人凭据、轮询游标和会话关联，不应公开或由多个服务实例同时使用。设置 API 复用原 Web 登录及 Host/Origin 校验，返回值不包含凭据。IM 凭据请求局部使用 SDK 原生采集抑制，避免 Telegram Token 和微信授权票据进入自动 HTTP 记录；其余请求保留原采集行为。

连接、任务处理、回复发送、入站媒体处理、输入状态、启动恢复及扫码失败会通过现有遥测猫上报；设置页网络故障或非 4xx 响应的解析故障也会报告。事件标注渠道、机器人和失败阶段，不附带 Token、二维码票据或聊天正文。正常取消、停止、微信长轮询超时和二维码过期不作为异常上报。

重启自动恢复已启用机器人的连接、游标和关联。已接收消息不自动重放；重启中断的任务回复需要在 Web 查看，必要时重新发送。发送结果未知时不自动重试。持久化来源与地址用于回看和归属，不提供离线投递队列或重启补发。

Telegram 支持文字输入与最终文字回复，微信另支持上述图片、文件、语音转写及引用上下文；长文字回复分段发送。暂不提供视频和原生语音发送、无转写语音解码、IM 按钮交互或 Web 发起任务的主动同步；扩展提出的交互仍可在 Web 会话回答。移除入站标记的输入改写扩展会导致 IM 无法确认回复归属，并提示在 Web 查看。

## 验证

```sh
node --experimental-strip-types --test tsgw/im/*.test.mjs
node_modules/.bin/tsc --noEmit --incremental false
npm run lint
```

浏览器回归使用已有开发服务器：

```sh
IM_E2E_URL=http://127.0.0.1:30141 node tsgw/im/e2e.mjs
```

来源角标回归需先以临时 `PI_CODING_AGENT_DIR` 启动开发服务，再将同一目录传给脚本；脚本只允许系统临时目录下的 agent 路径，会写入一个包含 Web、微信和 Telegram 消息的独立会话夹具：

```sh
IM_E2E_AGENT_DIR=<临时agent目录> IM_E2E_URL=http://127.0.0.1:30141 node tsgw/im/source-e2e.mjs
```

浏览器测试拦截全部 IM 管理请求，仅验证界面，不新增真实机器人。协议测试使用本地模拟响应；Pi 宿主集成测试使用真实 wrapper 与本地模拟模型。真实微信扫码、Telegram 收发需要配置真实账号后单独验收。禁止在开发工作树运行 `next build`。
