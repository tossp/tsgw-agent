# 上游整合

fork 保留上游全部功能与行为，只增加模块索引中列明的能力。冲突优先适配 fork 的接线；确有无法兼容的取舍时，先说明差异并取得决定，不禁用上游能力或恢复已撤去的替代实现。

模块职责、公共入口和各自的升级检查见 [TSGW 模块索引](../tsgw/AGENTS.md)。本指南维护通用整合流程，不按版本追加验收记录。

## 准备与整合

1. 核实仓库、目标分支、固定上游 ref 及其实际 commit。保护已有提交、未提交改动和其他工作树；`tsgw` 独立维护，不改为跟踪远程主分支。
2. 在本轮授权包含同步 `main` 时，将其同步到核实过的上游目标；从当前 `tsgw` 建立独立整合分支和 worktree，再合入该目标。重新初始化 `tsgw` 属于另一操作，不用删除重建代替常规合并。
3. 按变更领域读取 `docs/agents/` 和对应 `tsgw/<模块>/AGENTS.md`。保留上游运行时、界面、配置、安全及容器行为；fork 文件和必要外部接线分别核对，不顺带重构。
4. 对照 manifest 与 lock 精确安装全部 `@earendil-works/*` 包，包括 SDK 的关联依赖。版本以目标源码为准，不保留另一份版本表；保留 `tsgw-agent` 的包身份、独立源版本、Sentry 依赖和发布通道，避免无关依赖浮动升级。
5. 宿主接口变化时更新模块适配与接入清单；保留侧聊、真实子代理、shell、Stop、启动等待、摘要认证及消息投影的上游边界，具体检查由各模块规则承载。

## 验证

在最终整合快照上运行类型检查、lint、全量源测试及受影响模块的定向回归。界面变更运行相应浏览器入口；release/CAT 契约测试和真实 SDK 兼容测试不能由纯静态检查替代。

```sh
node_modules/.bin/tsc --noEmit --incremental false
npm run lint
npm test
node --test tsgw/release/*.test.mjs tsgw/cat-monitoring/*.test.mjs
```

Linux 下以 root 运行权限相关测试时，需仅对测试子进程去除 DAC 绕过能力，例如：

```sh
setpriv --bounding-set=-dac_override,-dac_read_search npm test
```

不改写或跳过权限断言。普通源测试不依赖预装 Chromium；需要浏览器的回归在安装浏览器后单独运行。

浏览器测试使用该工作树独占的开发服务、私有 agent 目录和合成会话；faux provider 与本地 CAT 传输拦截用于避免调用收费模型或外发测试数据。Turbopack 不接受工作树外的依赖软链，使用独立安装。开发缓存与 HMR 排障遵循 [根规则](../AGENTS.md#dev-server-troubleshooting)，不在开发工作树运行 `next build`。

生产构建、同一 tarball 安装/登录/PTY、远程 CI、真实供应商 OAuth、CAT 摄入、Docker 及跨系统行为分别核验；不要把本地源测试通过扩展为这些结论。生产验收方法见 [发布指南](../tsgw/release/README.md#本地生产验收)。

## 合并与收尾

- 核对暂存、未暂存和未跟踪文件，只提交本轮相关改动。合并到目标分支后确认最终 SHA 与已验收快照一致；合并适配有变化时补充对应验证。
- 已合并且干净的任务 worktree 和已合并临时分支随本轮收尾删除。需要保留的上游贡献分支或未完成成果应明确列出，不静默遗留，也不覆盖或强制清理改动。
- 合并不自动授予推送、发布、部署或重启权限。获准发布时跟踪对应 SHA 的 CI，并按 [npm 发布与 CAT 收尾](../tsgw/release/README.md#发布验收) 核验结果。
- 正式文档保留当前行为、设计取舍、操作步骤及仍有效的限制。已完成的实施顺序、逐轮审阅、测试次数、临时证据目录和一次性批准记录由 Git、CI 与会话历史承载，不复制成版本台账或归档文档。
