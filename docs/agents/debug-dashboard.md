# TSGW 任务大盘：信息覆盖、设计与验收

## 本轮授权与交付边界

用户将独立 `/debug` 定义为当前实例的任务大盘，而非上游 Debug 的简化版本；诊断是其中一层。上游已有信息是覆盖基线，并增加任务全景与较完整的视觉设计。用户允许适量 SVG、素材与动效，参考 `login2`，不以工作区极简风格限制大盘。

首轮整改已按后续授权发布并部署；本次密度整改在独立工作树完成前端实现与验证后，用户另行授权本地提交并合入 fork 分支 `tsgw`，不包含推送、发布或部署，不沿用旧轮次授权。**未经另行明确确认，禁止新增或调整后端接口、返回字段、参数和行为。** 模块外接入清单见 `tsgw/debug/AGENTS.md`，不修改上游 `DebugPanel` 或聊天生命周期。

## 数据来源与语义

- `GET /api/agent/debug[?session=]`：每 2 秒检查轮询，无并发叠加；首次观察到运行态时，优先选择正在执行、其次等待输入、最后其他驻留会话读取详情，之后由操作者选择或关闭，一次只观察一个详情。自动选择、过滤和目录浏览都只是既有 GET，不激活会话。summary 覆盖 wrapper 与 agent stream 登记，不代表所有任务和历史执行轮次。
- `GET /api/sessions`：每 30 秒读取目录、名称、项目、分支、普通／子代理／fork 关系与持久化子代理状态。页面标明目录接收时间与不同采样周期，不能将两接口当作原子快照。
- 本页真实观测：GET 请求耗时、成功／失败计数、在途时间、协议和页面可见性；明确不代表另一个聊天页面。
- 运行态指服务器持有对应信息，不等同正在执行；`running=false`、无 wrapper、目录存在或消失都不证明任务成功。下一次 idle 检查不等同关闭时间，Stop 强制关闭单独标注。
- 服务端读取失败可能回退空值，接口没有每源错误标志。因此使用“快照已更新／过期”等措辞，而非宣称整个实例健康。

## 页面方案

1. 紧凑品牌栏：保留档案视觉、时钟、新鲜度、复制与返回入口，桌面高度不超过 80px，不用大面积装饰占首屏。
2. 单行六项概览：普通会话、子代理分别计数，显示各自执行数量，并保留执行总数、等待输入、运行态总数和 SSE。缺少快照时不显示运行态零值。
3. 桌面固定三栏：左侧运行态任务家族、中间所选会话资源、右侧关注信号／观察页轮询／服务器资源。主框架在 1366×768 和 1440×900 一屏可扫描，长内容在对应栏内滚动；手机允许纵向阅读，不靠缩小正文字号。
4. 默认运行态，保留项目、状态、名称／最近活动排序与搜索。历史目录通过二级切换访问，不计为活动或成功。子代理使用自己的状态和检查时间；不驻留的家族根仅作父级上下文，不增加运行计数。多级子代理的可视缩进仍为根家族＋单层子行，直接父关系明确按 `relation` 显示；fork 独立。
5. 资源区优先 MCP 胶囊与释放条、回收检查倒计时及条、执行／等待标签；连接和进程历史等长明细原生折叠，完整信息仍可读取。正常连接灯保持稳定，连接中虚线呼吸、错误实线、释放点线，状态不只依赖颜色。
6. 右侧两种真实 GET 轮询分别显示耗时、慢／在途／失败、计数和样本；下次轮询检查不等于保证请求发起（隐藏页暂停，在途不叠加）。未观测状态不标正常；观察页状态不冒充其他聊天页客户端遥测。
7. 选中详情即使被过滤或离开运行快照，仍在独立资源区提供关闭入口；等待响应时不显示其他会话旧详情。所有选择只在本页内存，不写 URL，不发送任务命令。

视觉保留 `login2` 的品牌、双弧准星、编号与边角；按用户本轮追加意见改为现代深色控制台，而非暖白档案纸：石墨蓝背景、分层蓝灰面板、电青强调，紫色区分子代理，绿灯和橙红分别表达连接／等待／异常。大盘配色局限模块内部，不切换聊天工作区主题。渐变、细网格与光晕适度使用，文字对比和状态辨识优先。SVG 仅作装饰，不生成假指标；动效不阻挡阅读，不复制登录的开场等待或播报，减少动态效果时停止。需要保留键盘操作、可见焦点与手机无横向溢出。

## 已报告但本轮不实施的后端缺口

活动定时器／交接清单、跨页面客户端内存、普通任务完整运行轮次均缺少可靠既有来源。若后续必须支持，先给出具体契约变更、必要性及影响，用户确认后方可实施。不通过上下文 GET 补读历史：冷会话可能通过 SDK 迁移旧文件，且纯 custom 元数据也不会自动变成模型上下文结果，不能解决跨分支定时器历史和活动性问题。
