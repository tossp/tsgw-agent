# TSGW 任务大盘：信息覆盖、设计与验收

## 本轮授权与交付边界

用户将独立 `/debug` 定义为当前实例的任务大盘，而非上游 Debug 的简化版本；诊断是其中一层。上游已有信息是覆盖基线，并增加任务全景与较完整的视觉设计。用户允许适量 SVG、素材与动效，参考 `login2`，不以工作区极简风格限制大盘。

整改阶段授权前端实现、模块归位及验证；本地验收后，用户追加授权沿既有 `tsgw` 推送流程发布 `next` 并部署新川。**未经另行明确确认，禁止新增或调整后端接口、返回字段、参数和行为。** 模块外接入清单见 `tsgw/debug/AGENTS.md`，不修改上游 `DebugPanel` 或聊天生命周期。

## 数据来源与语义

- `GET /api/agent/debug[?session=]`：每 2 秒读取运行快照；单展开按需读取一个会话详情。summary 覆盖 wrapper 与 agent stream 登记，不代表所有任务和历史执行轮次。
- `GET /api/sessions`：每 30 秒读取目录、名称、项目、分支、普通／子代理／fork 关系与持久化子代理状态。页面标明目录接收时间与不同采样周期，不能将两接口当作原子快照。
- 本页真实观测：GET 请求耗时、成功／失败计数、在途时间、协议和页面可见性；明确不代表另一个聊天页面。
- 运行态指服务器持有对应信息，不等同正在执行；`running=false`、无 wrapper、目录存在或消失都不证明任务成功。下一次 idle 检查不等同关闭时间，Stop 强制关闭单独标注。
- 服务端读取失败可能回退空值，接口没有每源错误标志。因此使用“快照已更新／过期”等措辞，而非宣称整个实例健康。

## 上游能力覆盖与本轮新增

| 信息能力 | 既有来源 | 本轮展示与验收 |
| --- | --- | --- |
| 实例运行时间、alive／closing／starting wrapper | `DebugServerGlobal` | 服务资源区，保留全部数量 |
| Agent SSE、全部 SSE、文件监听 | 全局快照 | 概览与资源区分别标明，不混用 |
| 连接页面、地址、浏览器、页面标识、各类流数量 | `server.pages` | 连接诊断区，保留原信息 |
| 终端总数、监听、脱离、退出、清理时间 | `server.terminals` | 独立列表，不只放在悬浮提示 |
| 服务器 idle timeout、heartbeat | 全局快照 | 明示计时设置 |
| 运行、等待输入、存活、关闭、无 wrapper | summary | 指标、状态文字、列表筛选；不产生完成数 |
| 完整目录、名称、项目／分支 | `SessionInfo` | 新增目录层、检索、项目筛选、排序 |
| 普通／子代理、直接父会话、委派描述、fork 来源 | `SessionInfo.relation` | 保留运行态家族，并显示真实直接关系；fork 不挂成子代理 |
| 目录中子代理状态 | `relation.status` | 标为目录状态，不冒充普通任务完成语义 |
| wrapper 生命周期、启动次数、最近事件／命令 | detail | 保留并补齐显式进程历史 |
| idle 最近重置、实际 timeout、下次检查、Stop 强制关闭 | `wrapper.idle` | 显式计时详情，保留原行倒计时与提示 |
| 扩展 binding／bound／failed／none | wrapper | 全部状态可见，失败进入关注信号 |
| pending prompt、queued message、tool、bash、compaction、retry、replacement、UI wait | wrapper run | 保留原执行／等待标记 |
| wrapper listener 与流登记不一致 | detail | 补齐提示；不将正常正在连接误判为泄漏 |
| 流打开、连接、写出、丢弃、积压、来源 | `eventStreams` | 保留并补显式打开时间；积压本身不证明浏览器卡死 |
| 保活 provider、按文件登记、active／inactive／error | detail | 保留，错误汇总 |
| 子代理运行、profile、resume、后台、取消请求、MCP wait | detail subagents | 保留，并显示直接父关系 |
| 交回父会话的通知及等待时间 | detail notifications | 保留，补子会话来源 |
| MCP 状态、配置问题、错误／冲突、释放、宿主状态 | detail MCP | 显式展示，错误／配置问题进入汇总 |
| 当前快照故障与关注信号 | 已返回字段及本页请求 | 新增聚合，注明“全局快照＋当前展开会话”范围 |
| 观察页轮询耗时、在途、次数、失败、最后成功、实测曲线 | 本页读取器 | 新增；曲线只来自实际成功请求，最多保留 24 个样本 |
| 本页协议与可见性 | 既有浏览器读取器 | 真实测量；不冒充其他页面客户端状态 |
| 其他聊天页的心跳接收、重连、lease、watchdog、池压力 | 现有 GET 无来源 | 明示不可观测；不显示零或正常 |
| 全局活动定时器、跨会话交接状态 | 现有 GET 无可靠来源 | 明示缺口，不通过模型工具绕过只读边界 |
| 普通任务完整轮次与完成判定 | 现有 GET 无统一契约 | 不伪造任务计数或时间线 |

源码依据：`components/DebugPanel.tsx`、`components/debug-panel-state.ts`、`lib/debug-types.ts`、`lib/debug-snapshot.ts`、`lib/types.ts`；独立只读审计已逐项核对。

## 页面方案

1. 品牌头部：档案式控制中心标题、实时时钟、快照新鲜度、复制 JSON、返回工作区。
2. 六项概览：执行、等待输入、运行态会话、运行态子代理、SSE、仅目录条目。缺少快照时不显示运行态零值。
3. 关注信号：仅汇总有证据的异常，注明检查范围，不把“零信号”说成全局健康。
4. 任务全景：搜索、运行态／目录／子代理等筛选、项目、名称／最近活动排序；父子上下文不因排序拆散。目录条目明确未知运行态，历史子代理关系直接显示父会话，避免挂到无关历史条目下。
5. 右侧资源、连接及观察页诊断；窄屏改为单列。一次展开一个会话，展开与筛选只在页面内存中，不写 URL 或持久化状态。
6. 选中会话暂时不在筛选结果或最新列表时保留可关闭详情，不显示其他会话旧详情。

视觉参考 `login2` 的暖白档案纸、黑白双弧准星、橙色强调、编号与边角。SVG 仅作装饰，不生成假指标；动效不阻挡阅读，不复制登录的开场等待或播报，减少动态效果时停止。需要保留键盘操作、可见焦点、对比度与手机无横向溢出。

## 已报告但本轮不实施的后端缺口

活动定时器／交接清单、跨页面客户端内存、普通任务完整运行轮次均缺少可靠既有来源。若后续必须支持，先给出具体契约变更、必要性及影响，用户确认后方可实施。不通过上下文 GET 补读历史：冷会话可能通过 SDK 迁移旧文件，且纯 custom 元数据也不会自动变成模型上下文结果，不能解决跨分支定时器历史和活动性问题。
