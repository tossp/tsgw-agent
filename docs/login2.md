# Pi Web 第二套登录页

## 边界与入口

- 默认入口：`/login2`，可带 `?next=...`，只接受同源站内目标。
- 开启密码保护时，未认证访问首页由 `proxy.ts` 跳转到 `/login2`；原查询参数通过 `next` 保留。退出登录也进入 `/login2`。
- 保留原 `/login` 作为备用入口；密码校验、Cookie、限流和 API 的 401 行为不变。
- 右上角提供本项目 `tossp/tsgw-agent` 的 GitHub 链接，新标签打开且不授予 opener；与播报开关同组，不影响登录。
- `/login2` 及其静态素材不加入受保护的 matcher，页面仍通过现有认证接口确认状态，避免自重定向和素材被登录拦截。
- 无密码或已有有效会话时直接进入目标页面；不能把动画结束当作认证成功。
- 未认证时跳过动画进入原 `/login`；认证后可直接跳过余下动画进入目标页面。
- 本功能是 fork 的局部增量，不引入插件系统、新配置文件或运行时依赖。

## 实现

全部动画由 React 组件、状态和 CSS Modules 重现；无 iframe、注入脚本或第三方运行时。

- `app/login2/page.tsx`：React 页面、现有语言上下文和密码表单。
- `app/login2/PiAccessScene.tsx`、`pi-access.module.css`：原版三行品牌、暖白档案底板、中央状态、独立身份卡和 WELCOME 版式；含左上实时时钟。
- `app/login2/PiAccessReticle.tsx`：原版黑白双弧准星，按实际文字边界留出遮罩，避免长文案与圆弧相交。
- `app/login2/usePiAccess.ts`：阶段计时、请求取消和登录状态。
- `app/login2/pi-access-auth.ts`：只调用现有 `/api/web-auth`，成功后复查会话。
- `app/login2/PiAccessAudio.tsx`：默认尝试中文播报，受限时在正常页面交互中重试；用户可静音，失败不阻塞认证。
- `app/login2/pi-access-copy.ts`：本页专用三语文案，不扩散修改上游语言包。
- `public/login2/assets/`：原创生成的静态图片和音频。

序列为黑幕开场、洗白、访问许可、密码输入、请求接收、读取、核验通过、欢迎和揭幕。
只有密码接口与会话复查均成功，才能进入后半段；密码错误和 429 均停留在输入阶段。
没有音频 Promise 或动画事件参与认证判断。降低动态效果时跳过装饰序列。
按原版阶段分工：请求接收和读取展示中央标识，只有核验通过展示黑白双弧准星（9 秒和 5.4 秒反向匀速）。
准星由独立 SVG 遮罩避让标题和英文字幕，窗口尺寸或文案变化时重新测量，不修改整屏底色来盖住线条。
身份卡保留三行：身份令牌（现有访问密码输入）、身份编号（固定 9527）、权限等级（固定 3）。
身份编号仅显示于身份卡；右下角读取浏览器地址栏的 `window.location.hostname`，只显示主机名、不包含端口。
右下角同时显示请求来源 IP，复用已有 `/api/web-auth` GET 的 `X-Pi-Source-IP` 响应头，不额外发请求。
读取顺序：`X-Ts-Client-IP`、`CF-Connecting-IP`、`X-Real-IP`、`X-Forwarded-For`（首个地址）；不做可信代理校验，仅检查 IP 格式。
当前 Next 在缺少 `X-Forwarded-For` 时以连接的 `socket.remoteAddress` 补齐，因此直连也可显示；不可用时隐藏 IP 行。
编号、等级和来源 IP 仅用于展示，不参与认证或限流；全局限流逻辑不变。
窄屏和中等高度窗口按连接块实际高度为表单滚动区预留空间，避免遮挡按钮、错误提示；展示层不接收指针事件。
保留左上实时时钟、角标、档案色块、左下阶段计数、右下页脚及居中短进度条的位置关系。
真实密码验证替换原版装饰身份确认，不增加额外的授权点击；认证仍以原接口和 Cookie 为准。

每个语音阶段默认尝试播放；若被自动播放策略拦截，在页面点击、触摸结束或按键时直接重试，
无需专门点击播报按钮。只尝试当前阶段，不补播已经错过的语音，也不因后续交互重播已结束的语音。
播报按钮只控制用户的启用/静音偏好；主动静音后，普通交互、切换阶段或恢复页面可见均不自动解除。
隐藏页面或卸载会暂停播放；回到可见页面时，仅在用户未静音的情况下尝试恢复。
浏览器拒绝播放或资源加载失败时无声继续，不改写用户偏好，不影响认证和动画。可见文案始终提供全部必要信息。

## 上游同步与重放

同步 Pi Web 上游时，先保留或重新应用第二套登录页的新增文件，再保留默认入口适配：
`proxy.ts` 的未认证首页跳转和 `components/SettingsPanel.tsx` 的退出登录跳转均为 `/login2`。
检查现有 `/api/web-auth` 与 `safeLoginDestination()` 契约。
若上游改变接口，仅调整本目录的适配代码，不复制服务端密码逻辑。

运行：

```sh
node --experimental-strip-types --test app/login2/pi-access.test.mjs
node_modules/.bin/tsc --noEmit
npm run lint
node e2e/login2.mjs
```

浏览器脚本使用隔离的临时 agent 目录及测试密码，启动并停止自己的开发进程。
不要在同一 checkout 已运行开发服务时启动第二个 Next 进程，不执行 `next build`。
验收包括默认入口、退出后的重新登录、真实登录与限流、Cookie、站内跳转、
移动端、减少动态效果、音频自动播放/交互重试/静音及音频失败；原 `/login` 必须保持可用。
